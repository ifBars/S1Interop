# Compiler support and evidence

This experiment moves runtime adaptation into the build. Authors write ordinary C# against their local Mono game assemblies, including the original `ScheduleOne` namespaces. The IL2CPP build binds that source, maps referenced types from the installed metadata, lowers runtime-specific operations, and compiles the result against the IL2CPP wrappers. The original files stay unchanged.

There is no per-game-type wrapper catalog. A game update supplies the new reference metadata. The compiler still needs tested rules for each kind of runtime difference; automatic discovery is not a promise that every C# program already has a correct translation.

**Status: working prototype, not unlimited compatibility.** The same unmodified probe and library source pass 127 menu checks on Mono and IL2CPP **0.4.7f9**, with MelonLoader **0.7.3**. The Mono `alternate-beta` build was downloaded with SteamCMD and checked against the installed native beta. This establishes the behaviors listed below; it does not establish arbitrary gameplay compatibility.

The original goal is not complete. Metadata discovery removes the need to maintain a catalog of game wrappers, but does not remove compiler or runtime maintenance. Unity's [managed stripping](https://docs.unity3d.com/2022.3/Documentation/Manual/ManagedCodeStripping.html) can remove code from the shipped build, and its [AOT restrictions](https://docs.unity3d.com/2022.3/Documentation/Manual/ScriptingRestrictions.html) affect code generated at runtime and generic execution. This compiler does not restore absent native implementations. Matching Mono assemblies supply authoring signatures; executing their method bodies against native game objects would require an additional implementation that preserves object identity, dispatch, engine bindings, and shared state. That is not implemented or established by the current tests.

[Polyfill](https://github.com/DooDesch-Mods/ScheduleOne-Polyfill) by DooDesch separately repairs missing or changed API names in generated interop assemblies for older mods. Its documented limits include code removed without a successor; compatibility with S1Interop has not been verified.

## Authoring surface

Ordinary game namespaces, types, members, and generics are discovered from the referenced assemblies. Mod authors do not declare a wrapper for each game type:

```csharp
using System.Linq;
using ScheduleOne.NPCs;
using ScheduleOne.Employees;

var employees = NPCManager.NPCRegistry.OfType<Employee>();
foreach (var employee in employees)
{
    // Use the game members exposed by your matching reference assemblies.
}
```

| Behavior | Current implementation and evidence |
| --- | --- |
| Type/member names | Semantic metadata mapping, including nested types, aliases, static calls, and arbitrary referenced namespaces; portable contracts and real game builds |
| Nonpublic access | Local reference copies expose nonpublic types, fields, constructors, and nonvirtual methods; live checks call a private method and read private engine/game fields using unchanged source |
| Casts and patterns | Native identity for casts, `as`, `is`, top-level switch type patterns, and typed `foreach`; portable contracts and live casts/switch checks |
| Interfaces | Native interface proxy casts and implicit interface assignments; portable contracts and a live Button/IPointerClickHandler check |
| Reference comparisons | Built-in reference equality and `object.ReferenceEquals` compare native identity when both operands are proxies; overloaded operators retain their original dispatch |
| Collections | `List<T>` of native objects becomes a live native-backed view; scalar lists connected to native slots are selected by storage flow, preserving unrelated CLR lists; managed enumerators detect game-side mutation; explicit copies own new storage |
| Dictionaries | Dictionaries connected to native slots become live views with managed interfaces, key/value views, copied enumerator cursors, native version checks, and managed exception checks; unrelated dictionaries keep CLR storage and comparers |
| Default equality | Recognized hash-set, dictionary, and LINQ operations use the native default comparer for native keys/elements, including native equality overrides; explicit non-null comparers retain control |
| Delegates | Common callbacks convert automatically; a weak native-handle cache preserves equality for event removal; live removal works after a managed GC cycle |
| Authored events | Native delegate events lower to native-backed storage and accessor methods, preserving multicast removal, interface/override dispatch, and struct copies; cross-library subscription/removal exercised live |
| Coroutines | Managed `IEnumerator` arguments adapt to native iterator slots using the installed loader; `StartCoroutine`/`StopCoroutine` retain iterator identity, with nested iterators and native yield instructions exercised live |
| Mod libraries | A shared support DLL preserves collection types and callback identity across compiler-built mods; project references automatically pair native binaries with verified original authoring metadata |
| Components | Direct, non-generic MonoBehaviour subclasses get registration and constructors; managed state, `Awake`, helper properties, and rediscovered component identity are exercised live |
| Serialized fields | Primitive, string, mapped scalar enum, primitive scalar array, mapped enum array, and mapped Unity object reference fields in supported components use native storage automatically, including nonpublic `[SerializeField]` fields; initializer order, cross-library access, JSON overwrite, runtime cloning, and retained strings under native GC have separate evidence |
| Updates | References are read on each build; mismatched game versions or stale/missing MelonLoader generation records stop the build |

## Architecture

- `src/S1Interop.Compiler`: Roslyn binding, metadata mapping, semantic transformations, and diagnostics. It does not write project files or execute game assemblies.
- `src/S1Interop.Cli`: the single CLI, with an out-of-process `compiler` command group. It reads file lists from MSBuild and writes generated source, shared support, and authoring metadata under `obj`.
- `build/S1Interop.Compiler.props` and `.targets`: opt-in game references, original-source IDE references, runtime-separated outputs, version checks, and replacement of compiler inputs for IL2CPP builds.
- `tests/S1Interop.Compiler.Tests`: executable, authored runtime contracts plus a separate compile-only lane for local game references.
- `tests/S1Interop.Compiler.RuntimeSmoke` and `.RuntimeLibrary`: the same two-project source compiled for each backend and exercised in the game's menu.
- `samples/SourceCompiler`: a small mod that uses ordinary game namespaces and casts.

The experiment produces two mod DLLs from one source tree. Each DLL declares its MelonLoader runtime. The managed type identities in Mono and the generated IL2CPP proxy assemblies differ; selecting a DLL is a packaging concern and does not require conditional mod source.

Before compilation, selected game references are publicized into local `obj` copies using Mono.Cecil. Original files are never replaced. Executable IL bodies and embedded resources are removed, and the copies carry a reference-only marker that prevents runtime loading. Cache keys include source hashes and the transformation version. Format 5 also retains original nonpublic field visibility as metadata, so reflection analysis does not mistake publicized fields for originally public fields. Normal builds regenerate earlier cached references automatically; direct compiler callers must prepare old publicized references again when reflection analysis requires that missing metadata. Generated access attributes and compiler settings enable the resulting mod to call the original loaded assemblies. The f9 build prepares 134 selected references for each backend without maintaining a list of individual game members.

Virtual methods retain their original accessibility so protected overrides remain valid. Fields sharing an event or property name also retain their accessibility to avoid ambiguous source binding. Those cases still limit direct nonpublic access. Publicization does not make absent native code exist or change readonly semantics. Keep all generated game reference copies local; they are not mod runtime dependencies or redistributable SDK assets.

IL2CPP outputs share a generated `S1Interop.Runtime.dll`. Its generic collection, cast, delegate, and equality support references IL2CPP infrastructure and the framework, without referencing game types or Unity API assemblies. Each lowered module checks the support implementation signature before its code runs. A different support generation fails explicitly rather than silently sharing incompatible caches or collection types. The signature covers support source, native handle representation, and relevant infrastructure assembly identities; this is not a general verifier of the installed loader's behavior.

Compiler-enabled project references produce a metadata-only companion in `.s1interop/authoring/<assembly>.dll`. The native assembly records its SHA-256. Dependency binding verifies the hash and assembly identity, substitutes the original signatures, and copies companions for referenced dependencies. Missing or stale companions fail with `S1C908`. Keep this directory with a library distributed to mod developers; players do not need it. The native build disables SDK reference-assembly output so dependencies resolve beside their companions. Arbitrary package layouts and design-time dependency resolution in an IL2CPP IDE configuration need further validation.

The existing CLI migration and source-generator packages retain their current behavior. This import is experimental and is used instead of the generator package's game-reference setup. Projects with additional generators or backend-specific dependencies need separate integration work before this build path can replace their existing configuration.

Authored events whose delegate maps to a native proxy use generated accessor methods because CLR events require a CLR delegate type. Field-targeted and accessor-targeted attributes are retained. Event-only attributes fail with `S1IC022` rather than being silently discarded. Original authoring companions retain the event declaration for consumers, and generated accessor markers resolve private-name collisions across assemblies. Runtime `GetEvent`, Harmony event-accessor discovery, and general event metadata equivalence remain unsupported.

Dictionary storage is selected by source flow rather than by the key/value types alone. Native reads, assignments, author parameters/returns and compiler-library signatures connect aliases. Keys, values and explicitly typed enumerators follow their owning storage. `new Dictionary(source)` remains an independent copy; `ToDictionary` feeding native storage preserves its selected comparer. The live probe verifies string dictionaries through a separately compiled library and ordinal-ignore-case lookup after native assignment.

Default comparers, native comparer views, and built-in ordinal string comparers have direct native projections. Other managed comparers use generated, non-generic injected adapters for each supported closed key type discovered in native dictionary storage. Factories register through the shared runtime without native calls at module load; injection happens when a custom comparer is first used. The original comparer identity is recoverable across compiler-built libraries. Portable tests cover string and native-object keys, opaque comparer arguments, and custom comparers used with `ToDictionary`; a live string-comparer check exercises callbacks and identity after managed collection.

The installed Il2CppInterop uses mutually strong handles for injected objects and their managed peers. The adapter replaces its own handle with a weak handle while a separate interface wrapper holds the native object. Its conditional cache therefore need not permanently root the native object. This uses the installed runtime's private handle field with a type check; an incompatible layout is rejected. A separate native-only harness verifies retention, native reclamation, managed comparer reclamation, and adapter recreation across forced collection on the game thread for five string-comparer instances. Concurrent collection stress and other key shapes are not yet verified. The runtime's injected callback trampoline also suppresses thrown managed exceptions; exception parity for throwing comparers remains unresolved. Author-declared/generic key shapes, nested collection values, opaque/generic storage flows, all BCL dictionary methods, and exact CLR type/reflection identity remain unfinished. Portable tests use distinct native exception stand-ins to verify ordinary duplicate, missing and null-key failures remain catchable as managed exceptions.
Rank-one primitive scalar and compatible mapped enum arrays connected to native array slots now use native storage throughout tracked local, field, parameter, return, and compiler-library flows. Ordinary source allocation and initializers create that storage automatically. Aliases observe shared mutations. Direct equality comparisons, object.Equals, and explicit hash-code calls use native identity; default comparers inside opaque object-keyed collections still need adaptation. Supported operations include indexing, enumeration, dimensions, connected casts and patterns, overlapping `Array.Copy`, `CopyTo`, `Clear`, `Clone`, and `Resize`. Mixed CLR/native copies explicitly copy elements while unrelated managed arrays retain their CLR representation. The same source probe verifies shared storage in a game-owned array field through a separately compiled library on both f9 backends.

Mapped enum arrays require an exact mapped native enum and matching underlying type. They use the same native scalar storage helpers, preserving aliases and fresh clone/resize behavior. Portable tests include nested and 64-bit enums, layout mismatch rejection, and explicit rejection of cross-enum copies. Integer/enum cross-copies and abstract native enum-array return slots remain unsupported. The live probe uses Schedule One EQuality arrays in a compiler-built component library, checking shared mutations, independent cloning, Unity JSON serialization, and replacement while an old alias remains alive. This does not add authored enum registration or scalar enum field injection.

Rank-one arrays of existing mapped, non-generic native reference classes also use native storage. Checked element access preserves null/bounds exceptions, assignment evaluation order, null-coalescing assignment, and direct null-conditional reads. Stores check the actual runtime element class before calling native `Array.SetValue`, which performs the write barrier. Covariant views share storage; clones preserve the runtime element class, while resizing allocates the declared element class. Copy helpers preserve overlap and partial-copy failures, including mixed CLR/native arrays and covariant CLR destinations. Generic native APIs returning abstract array wrappers are adapted without copying their storage. The live probe exercises game data arrays through a compiler-built library on both backends, including a mixed copy after managed collection.

Post-binding verification still rejects hidden snapshot conversions with `S1IC032`, including unadapted CLR library and delegate signatures. `S1IC033` identifies unsupported native-array operations and memory views. Element refs, spans, mutable collection interfaces, general opaque/generic flow, string/struct/interface arrays, authored or unmapped enum arrays, generic or authored reference element classes, nested conditional receivers, and additional `System.Array` methods need further adaptation. Injected component fields also support rank-one arrays of mapped Unity object references, including private serialized fields, inherited storage, JSON restoration, and clone reference remapping. Arrays of other serializable classes and authored component elements remain unsupported. Ref and span conversions cannot simply expose native memory: unlike a CLR array byref, that pointer does not retain the native array's owner. Scalar copy helpers keep wrappers alive while accessing spans, and reference helpers retain their wrappers through native calls. This is not general array parity.

## Build integration details

The props select `netstandard2.1` for Mono and `net6.0` for IL2CPP unless the project explicitly supplies a framework. The tool requires .NET 8.

Configuration names containing a `Mono` or `Il2Cpp` word also select that runtime, including `Debug Il2Cpp`. An explicit runtime contradicting the configuration fails with `S1C906`. Build the two runtimes serially: NuGet restore state is still shared by the project.

Both outputs bind Mono author source. Before lowering and C# compilation, the imports select `MONO` and remove `IL2CPP`, including the symbol the SDK adds for an `Il2Cpp` configuration. Existing mods therefore use their Mono source branches without a project-specific workaround. Other custom, debug, and framework symbols remain intact; target-framework conditionals can still differ between outputs. The generated MelonLoader domain attribute independently identifies the actual output runtime. New mods do not need either runtime conditional.

Outputs go under `bin/<configuration>/<runtime>/<framework>/`; generated inputs use the corresponding `obj` directory. Builds do not deploy into a game install. Put the selected mod DLL in `Mods`, its mod-library dependencies in `UserLibs`, and the IL2CPP output's `S1Interop.Runtime.dll` in `UserLibs`. A Mono build does not require this support DLL. Use one compatible support generation for all compiler-built mods. Do not ship local game references, generated interop assemblies, the authoring companions as runtime libraries, or the compiler.

Original source is checked with the project's requested C# version. The lowered compilation uses C# 9 or newer for generated module initialization; authors do not need to change their source language syntax. This path has not been integrated with arbitrary analyzers, signing settings, or source-generator pipelines.

The version gate reads the installed game's serialized version and fingerprints both game assemblies. It rejects differing versions (`S1C905`) and checks the SHA-512 native image hash recorded by MelonLoader after generation (`S1C907`). An absent or mismatched record requires launching that install with MelonLoader to regenerate its interop assemblies. A matching generation record is provenance evidence, not proof of every generated method's behavior.

## Verification

```powershell
dotnet run --project tests/S1Interop.Compiler.Tests -c Release
dotnet run --project tests/S1Interop.Compiler.Tests -c Release -- --filter NativeAs
dotnet run --project tests/S1Interop.Compiler.Tests -c Release -- --real <mono-install> <il2cpp-install>
```

Portable tests execute against small authored contracts; they never instantiate actual native wrappers. The real-reference lane emits a DLL without loading it. The menu probe separately checks actual runtime behavior. These are distinct forms of evidence, and none by itself proves arbitrary gameplay, networking, save serialization, or content creation.

### Packaged project adoption

The compiler CI also installs the actual candidate package into an isolated tool/cache directory, creates a default project, restores its local tool manifest, verifies its embedded build assets, and exercises reference preparation from the package:

```powershell
dotnet pack src/S1Interop.Cli -c Release -o artifacts/compiler-packages
./tests/Test-CompilerPackage.ps1
```

Pass both `-MonoGamePath` and `-Il2CppGamePath` to additionally build the generated project against real installations. Those optional checks produce compile evidence; CI does not have game installations. The script removes its temporary project and cache afterward.

`Run-CompilerRuntimeSmoke.ps1 -StarterLoad` can load an already-built, unmodified generated starter in a dedicated marked test installation. It checks the starter's ordinary initialization message and the loader runtime, records deployed hashes, and removes its deployment. It does not require the larger runtime probe library. Stale loader logs are preserved before launch so a prior initialization message cannot satisfy the check. This route has passed on both verified f9 backends; it establishes initialization only, not the F8 gameplay action or arbitrary mod behavior. The default runner mode continues to require the probe's token-tagged runtime-contract result.

### Existing mod corpus

The checked-in [SteamNetworkLib runtime harness](../tests/S1Interop.Compiler.SteamNetworkSmoke/README.md) builds an audited copy of the real library without importing its deployment-enabled project. `tests/Test-CompilerSteamNetwork.ps1` records source and artifact hashes, builds both backends serially, and optionally runs the local transport-override probe in dedicated test installations. It removes its temporary source/build copy and retains ignored evidence. This makes the 27-check live case reproducible without committing the library or game sources; it does not exercise Steam transport or voice.

The audited streaming-buffer selection contains 50 unchanged files with `SCHEDULE_ONE_INTEGRATION` enabled. All 31 checks pass on both verified 0.4.7f9 backends: clip creation, sample writes, padded silence and reset join the existing transport-override checks. The native build now restores the failed `AudioClip` event accessors automatically. These checks do not exercise Steam voice, playback, the audio thread or multiplayer.

Mapped callback array parameters use the native shared-storage representation required by their delegate signatures. The generated delegate cache also breaks the installed bridge's mutually strong ownership cycle while preserving callback identity. Portable contracts cover supported callback shapes and incompatible bridge layouts; a separate native lifetime probe verifies field-only retention and reclamation after removal. Unknown bridge layouts and handle allocation failures are rejected. Reclamation after arbitrary allocation failure or an unknown post-conversion bridge is not guaranteed.

Compiler reference preparation records hashes and original-image paths beside metadata-only compile references. During `compiler lower`, `AtomicEventRepairPlan.Create` analyzes those original images and emits startup instructions for failed accessors whose complete source instance or static event loop matches the supported atomic pattern. Original assembly inputs can be analyzed directly. Publicized format-3 references embed the original-image hash and require a matching provenance sidecar; missing, changed or corrupt provenance stops the build. Raw and prepared copies of identical images deduplicate, while conflicting images with the same assembly name are rejected. Framework reference packs and metadata-only authoring companions are excluded. Older unmarked publicized references must be regenerated; normal project builds recreate the current format automatically. No original game IL or machine paths are copied into the mod's repair initializer.

At startup, the shared runtime verifies the loaded wrapper hash and module ID, method token and signature, exact native field owner/type, and native object CAS overload. It patches the managed throwing wrapper method, covering internal wrapper calls such as `AudioClip.Create`. Compatible repeated registrations reuse the installed repair. Unsupported or mismatched installations stop initialization; rebuild against the current verified game pair. The original installation assemblies remain unchanged. The f9 build plans 190 accessors, including 110 static accessors. Static updates initialize the owning native class and use its exported static-field storage plus the metadata offset; thread-local fields, generic owners and unsupported layouts are rejected. The shared core probe tests duplicate subscription, single removal, native dispatch and absent-handler removal on `AudioSettings.OnAudioConfigurationChanged` and passes 127 checks per backend. PCM accessors also have dedicated reconstruction coverage. Other planned accessors lack behavioral coverage, and throwing static constructors, competing static updates and arbitrary-thread collector behavior remain unverified.

The [native atomic event diagnostic](../tests/S1Interop.Compiler.NativeAtomicEventSmoke/README.md) passes 29 checks, including add/remove, forced competing updates, lifetime, a controlled collection between raw pointer read and wrapper acquisition, and source-planned PCM reconstruction. That interleaving is not a universal collector guarantee or a test of every background schedule. The delegate cache's separate pointer-acquisition window remains uninstrumented.

`UnstrippedMethodAnalysis` also identifies failed wrappers beyond supported event loops: the verified audio/core modules contain 32/241 throwing stubs with paired Mono bodies. This inventory is not full reconstruction or complete reachability analysis. Other managed bodies, generic event owners, virtual dispatch, reflection and cross-assembly call analysis remain incomplete. Direct `Type.GetField` can now adapt supported private event backing fields to native storage. The analysis reads physical reference metadata without changing C# accessibility and verifies the field signature before using an event symbol for its type. The AudioSettings probe reads, replaces and clears callback storage through reflection, verifies native dispatch observes the writes, and restores the original callbacks. This remains narrower than full reflection equivalence.

Storage analysis now treats fixed-type members of constructed generic methods/classes as the same source declaration. For example, `Read<T>(byte[] values)` retains shared storage across calls with different type arguments. Members whose storage type changes with `T` remain separate and require further adaptation. The live library probe routes a game-owned scalar array through a generic helper and checks its existing alias and mutation behavior on both runtimes.

Source `Func` and `Action` values propagate supported collection storage through their invocation parameters and return values. Connected fields, method parameters, method groups, lambdas, delegate constructors, and returned callbacks retain native storage; unrelated CLR callbacks stay unchanged. Factory method arguments remain separate from the callback's arguments. Compiler-built library metadata carries these signatures across assembly boundaries. Portable contracts cover conditional calls and reduced extension method groups; the live probe checks a callback mutating and encoding an existing byte-array alias across a library boundary. This does not establish arbitrary custom-delegate, variance, reflection, or nested-container support.

Connected byte-array `Convert.ToBase64String` overloads read native storage directly, including slices and formatting options, while keeping its owner alive. Validation tests cover null, range, option, and exception-parameter behavior; exact exception message text is not a compatibility guarantee.

Connected `BitConverter.GetBytes` results transfer into native storage before author code receives them. The inspected [.NET 6 implementation](https://github.com/dotnet/runtime/blob/v6.0.0/src/libraries/System.Private.CoreLib/src/System/BitConverter.cs) allocates a fresh result. Native byte-array reads support the `ToBoolean`, `ToChar`, signed/unsigned 16/32/64-bit integer, `ToSingle`, and `ToDouble` overloads taking an array and start index. They use bounded spans internally and retain the native owner through the call. Tests cover values, fresh allocation identity, named-argument order, shared mutation, and null/index/short-buffer exception types and parameter names. The live probe verifies integer reads and short-buffer validation across a compiler-built component library on both backends. Other overloads, including native-array `ToString` and `ToHalf`, remain unsupported; exact exception messages are not promised.

Connected `Convert.FromBase64String` results transfer into native byte-array storage before author code receives them. The original decoder still performs validation; its result is a fresh allocation on the inspected Mono and .NET 6 implementations, including empty inputs, so the transfer does not separate existing aliases. Other methods returning borrowed or cached buffers do not get this treatment. Direct `Encoding.UTF8.GetString` calls read native storage through a bounded span and keep its owner alive until decoding finishes. Named-argument evaluation order and null/range validation are covered. Custom or indirectly supplied encoding receivers remain diagnosed because their array and span overloads may differ. The live library probe checks Base64 creation, shared mutations after managed collection, UTF8 reads, and distinct empty-buffer identity on both game backends.

`AccessTools.Field(typeof(T), constantName)` and direct `typeof(T).GetField(constantName, flags)` adapt supported mutable fields exposed as native properties when the result stays in a local or private readonly source-defined `FieldInfo` cache used only for null checks and ordinary `GetValue`/`SetValue` calls. Cached fields are tracked across source files and constructed generic containing types; assignment results cannot escape into other values. Reflection that dynamically inspects the authored cache itself is outside this analysis. Conditional calls, null patterns and nullable suppression are supported. Direct lookups apply runtime visibility, instance/static, inherited and declared-only flags using the original field metadata; excluded fields return null. Flags expressions are evaluated once. Exact-name lookups distinguish fields whose names differ only by case. Unique-name `IgnoreCase` lookups are supported; shadowed exact names and ambiguous case-insensitive lookups still require further adaptation. Explicit `FieldInfo` local declarations remain valid. The compiler resolves inherited fields to their declaring type, verifies the native accessor types, and uses a shared accessor adapter. Native base wrappers are rewrapped to the required native class for reflection targets and values. The adapter cannot supply a real native field handle or original custom-attribute metadata, so metadata inspection, aliases, and escaping field descriptors remain diagnosed rather than silently exposing synthetic metadata.

Reflected `List<T>` and `Dictionary<TKey, TValue>` storage uses the existing live collection views when native element types match supported scalars, mapped classes or mapped enums. Reads preserve identity and game-side mutations; writes preserve aliases rather than copying into detached collections. Storage analysis follows descriptor caches, nullable suppression and negated declaration patterns. Mixed managed/native descriptor caches and statically known derived CLR collection writes are diagnosed. Opaque values produced by external managed code, arbitrary collection subclasses, constant-name reflected arrays and general descriptor flows still need adaptation; a plain CLR collection that reaches the native write hook is rejected instead of silently copied.

Dynamic names are also supported for `typeof(T).GetField(name, flags)` and `AccessTools.Field(typeof(T), name)` when the type is known at compile time and the descriptor stays in the supported read/write flow. The compiler generates candidates from the original field metadata, preserving visibility, inheritance, hiding, case ambiguity, null-name behavior and written argument evaluation order. Generic helpers can read and replace supported lists, dictionaries, scalar arrays and mapped reference arrays without copying away their aliases. The live menu probe checks a replacement console dictionary and the Forklift helper shape on an inactive `LandVehicle`, including shared wheel-array storage and a scalar steering field. It restores the original console table and destroys the temporary objects afterward.

Generic methods whose parameter or return type is a method type parameter, such as `T Identity<T>(T value)` or `T Make<T>() where T : new()`, track storage separately for each invocation. A call connected to game storage can use a native collection or array while an unrelated call to the same helper keeps its CLR type. Supported extension receivers, nullable type arguments, null-conditional calls and nested helpers follow the same flow. Body-imposed native storage still propagates to callers, as in the dynamic field helpers. The live probe checks a generic dictionary factory, an independent CLR list factory, and array aliases passed through an identity helper and extension receiver into a compiler-built library. Nested containers such as `List<T>` parameters, generic class members and generic method-group conversions still need broader adaptation and tests.

`S1IC034` diagnoses unsupported tracked or escaping lookups when metadata identifies a field-to-property change, including computed field names. A dynamically selected field with an unsupported representation throws `NotSupportedException`; generating a candidate catalog does not make every field shape usable. Other reflection entry points, including `GetFields`, `GetMembers`, `InvokeMember`, `AccessTools.DeclaredField` and dynamically obtained types, are not automatically adapted or comprehensively diagnosed. Readonly fields, native storage with a different value representation, dynamically computed types, and general Harmony Traverse chains need further adaptation. The MoreXP-derived runtime checks exercise the two Recycler fields; the whole mod has not been exercised in gameplay. BiggerLobbies also has the narrow traversal runtime evidence below. It never stops an existing game process, uses a unique result token, records all deployed DLL hashes, and removes its unchanged deployed DLLs afterward. Checks cross a separately built library boundary, including callback conversion in either module and removal in the other, plus an injected coroutine method group, live string/integer lists, abstract component inheritance, authored multicast events, and live dictionaries. The compiler's 220 portable contracts also cover cross-mod support identity, rejection of mismatched support before mod execution, missing or stale authoring companions, deterministic, non-executable publicized references, and consistent authoring symbols through the actual MSBuild hooks. Private constructors and nested types, event subscriptions, and protected overrides are tested against original unmodified contract assemblies. These counts describe the current tested implementation, not coverage of every game member or language feature.

Generic method groups now use storage slots specific to each delegate conversion. Contracts cover explicit and inferred type arguments, generic factories, closed extension receivers, aliases merged through generic helpers, and independent CLR delegates. The shared live probe uses a generic delegate factory and closed extension delegate for the game command dictionary, plus an inferred generic delegate for a byte-array field in a compiler-built library. Both runtimes pass 127 menu checks. This supports helpers whose parameter or return type is the method type parameter itself, such as `T Identity<T>(T value)`; it does not specialize arbitrary generic bodies.

Direct calls to eligible private static helpers with `List<T>` or `Dictionary<TKey, TValue>` signatures now get separate generated method copies when connected to native storage. The copies retain their generic parameters and constraints, preserving generic overload binding instead of substituting concrete types into their bodies. The original methods remain available to CLR calls. Contracts cover shared mutations, independent CLR calls, ordinary recursion, and preservation of already-selected nested call rewrites. The live command-dictionary probe also passes through a private generic dictionary helper on both runtimes.

This specialization currently requires closed, representable method arguments and a nongeneric containing type. It excludes attributed, partial, async, iterator, extension and caller-info-sensitive methods, interface owners, and directive-sensitive containing types. Open generic helper chains, polymorphic recursion, generic containing types, and collection method-group specialization remain gaps. Generated private copies also change the reflection and stack-trace surface; method metadata identity is not preserved. These are compiler implementation limits, not a requirement for mod authors to maintain runtime-specific source.


Immediate `Traverse.Create(root).Field(constantName).GetValue<T>()` reads now adapt when reference metadata verifies the field-to-property representation. This covers the unchanged BiggerLobbies Mono expression for `_lobbyService`. The runtime uses the native field owner instead of blindly selecting a same-named property, preserves null roots and Type-root behavior, and rewraps native values for typed reads. Compatible list and dictionary fields use live collection views, including object-typed results and supported managed interfaces. Portable contracts check shared mutations, repeated-read identity, replacement, null values, incompatible list/dictionary/array casts, and single evaluation of the root. The live probe checks the game console command dictionary through Traverse on both f9 runtimes and restores the original table afterward. Portable contracts also cover field/property shadows and interface proxies.

Collection adapters follow the runtime field type when a derived field hides a base collection with another list, dictionary, or scalar. Those shadow cases use authored fixtures; the live console probe exercises the normal dictionary path.

A field owner not represented in the root's wrapper hierarchy remains unsupported; unknown runtime types, arbitrary traversal chains and full reflection identity are not established. Recognized unsupported field traversal descriptors produce `S1IC041` rather than silently returning an empty traversal.

## Semantic requirements

The compiler must preserve native object identity, Unity's overloaded null behavior, expression evaluation count, collection mutation, delegate removal, exception behavior, and callback lifecycle. A successful target compilation cannot establish all of these properties.

Coroutine adaptation uses MelonLoader's registered `MonoEnumeratorWrapper` from its installed `Il2Cpp` support module. The compiler adds the reference automatically; do not redistribute that loader module with the mod. Iterator caching uses weak managed references and weak native handles, with periodic cleanup, so the cache itself does not create a strong cross-runtime ownership cycle. The live probe starts and stops a coroutine through the same iterator after managed GC, executes a nested iterator, and resumes after `WaitForSeconds`, all on the original owning `MonoBehaviour`. This does not prove arbitrary iterator disposal/exception equivalence or concurrent native-GC behavior. Loader restrictions on yielded objects remain: unsupported managed values are not silently converted. An injected parameterless `IEnumerator Start()` is split into a hidden managed iterator and a native Unity callback. Ordinary direct calls and method groups still resolve to the managed iterator, including calls from separately compiled S1Interop libraries; `nameof(Start)` remains unchanged. The live probe verifies automatic Unity invocation across frames and a cross-library method group. Compiler-built dependency assemblies are registered through MelonLoader's readiness queue before consumer code runs. Reflection sees the generated native callback and helper, so reflection-based lookup is not equivalent to the original source.

Native methods and properties returning `IEnumerator` now expose a managed view automatically, including typed declarations, `var`, reassignment, returns, and null-conditional reads. The view forwards `MoveNext`, `Current`, and `Reset`; it exposes `IDisposable` only when the native iterator implements it. Passing the view back unwraps the same native iterator, and a managed iterator returned through a native slot recovers its original managed instance. Weak caches preserve live identity. Portable contracts verify aliasing, reset, round trips, and disposal executing a finally block. Two live checks step a native game coroutine and dispose it through managed interfaces. Primitive values boxed in the native heap, arbitrary IEnumerator casts, and native iterator-producing method groups still need adaptation.

Scalar list selection follows assignments, local/field/property storage, author parameters and returns, local functions, conditional choices, and matched native or compiler-library slots. It does not switch every occurrence of a closed List type in a module. Unrelated CLR lists and `typeof(List<string>)` remain unchanged. `new List<T>(source)`, `ToList`, and `ConvertAll` retain copy semantics; native storage is never detached by an implicit snapshot. Portable tests cover integer/string aliases, public library signatures, property initializers, copies, mutation invalidation, and nongeneric IList value checks. Real checks use an isolated DeveloperSettings ScriptableObject and a VertexHelper, with no game-state or save mutation. The scalar eligibility rule includes strings, booleans, characters, and built-in integer/floating-point types; live evidence currently covers string and int, not every eligible native generic instantiation.

Component chains may now inherit from author-defined MonoBehaviour classes or verified compiler-built libraries, including abstract bases. Generated pointer constructors retain each base constructor body and field initialization; ordinary virtual calls and inherited Unity callbacks retain managed dispatch. Abstract classes keep their CLR abstract contract. Their abstract methods/accessors remain hidden from native registration, while concrete overrides are exposed. Generated static initialization registers abstract types and, when the installed Il2CppInterop version accessor is available, restores the native abstract flag before descendants register. This avoids two defects observed in the installed loader: missing abstract class flags and insufficient allocation for newly introduced abstract vtable slots. The native representation intentionally does not expose the abstract declarations themselves; this is not reflection or native metadata equivalence. Live f9 evidence covers cross-library Awake and IEnumerator Start overrides. Portable contracts additionally cover a three-level chain and a partial base with an authored static constructor.

Where a transformation is not implemented, a build error is preferable to a silently copied collection, dropped callback, or guessed member name. Current boundaries include:

- Collection adaptation beyond native-object and tracked scalar `List<T>` and tracked `Dictionary<TKey, TValue>`, including nested collections, array shapes beyond tracked rank-one primitive scalars, query syntax, arbitrary enumerable interfaces, and collections flowing through unhandled generic/delegate/opaque boundaries. A precompiled external library expecting a CLR `List<T>` does not automatically accept the native-backed view; compiler-built libraries can share it. Supported LINQ adaptation is not universal interface adaptation.
- Equality through arbitrary opaque objects, unknown generic algorithms, ordering, and reflection. Recognized default hash and equality operations are adapted, but that does not establish every possible `Equals` dispatch or collection algorithm.
- Nonpublic virtual members and fields whose names collide with events or properties. Publicization intentionally preserves their original accessibility; it is not yet a complete nonpublic authoring surface.
- Component bases outside supported author/compiler-library MonoBehaviour chains, native interface implementation, generic/nested components, arbitrary constructors, and serialization beyond supported primitive/string and mapped enum fields, rank-one primitive scalar or mapped enum arrays, mapped Unity object references, and rank-one arrays of those mapped Unity object references. Unsupported explicit serialization fails with `S1IC015`; unsupported public serializable fields warn with `S1IC016`. Runtime-only fields can use ordinary `[NonSerialized]` declarations. By-reference access to lowered fields fails with `S1IC017`; ambiguous inherited field names and incompatible constructor shapes fail with `S1IC018`. `SerializeReference`, other array shapes, same-compilation authored component references (including self/cyclic registration), author structs/enums, and prefab/AssetBundle script binding remain unsupported.
- Complex nested native patterns, `ref` write-back to proxy properties, all delegate shapes and event reflection metadata, native iterator method-group adaptation and boxed-value conversion, iterator-based Unity messages other than the supported `Start()` shape, callback lifetime under concurrent native GC, source-generator integration, and backend-specific dependencies.
- Reflection and dynamic binding equivalence, native-to-managed exception type translation, Harmony patches across every method shape, native generic instantiations unavailable in the AOT image, and game code removed by native stripping.

The original source remains the IDE authoring surface. Generated source is inspectable under `obj`; source mappings do not yet provide complete statement-level debugging parity after structural transformations.

No per-game API catalog needs updating when a member is added to the reference metadata. However, the compiler's semantic rules and its MelonLoader/Il2CppInterop dependencies still require maintenance when runtime contracts change. Metadata alone cannot restore code absent from the native executable. These are unresolved parts of the requested maintenance-free, unlimited experience, not hidden exceptions to a compatibility claim.

A native-only lifetime diagnostic lives in `tests/S1Interop.Compiler.NativeLifetimeSmoke`. It directly references the installed native runtime and the already-built compiler library; it is test instrumentation, not a conditional authoring example. Five string-comparer cases run through retained, released, and recreated phases with both managed and native collections. On the verified f9 runtime, all cases passed over 20 frames: released native adapters cleared on the first drain frame and unrooted managed comparers cleared on the second. The two deliberately rooted comparers recreated working adapters and then reclaimed cleanly after their roots were released. This supplies native finalization evidence beyond the ordinary probe's managed-GC checks, without establishing concurrent or exhaustive lifetime behavior.
Supported serialized component fields now lower automatically to native storage. The author keeps ordinary fields and initializers; generated accessors preserve reads, assignments, compound operations, patterns, and cross-library access. Managed staging preserves initializer order and base-constructor virtual access, transfers each initial value once, then releases the staged reference. Nonpublic `[SerializeField]` fields retain their original serialized names through public native backing fields; generated runtime reflection metadata differs from the authoring contract. `[NonSerialized]` fields remain managed state.

The reference-array extension also verifies a ScriptableObject retained only through a compiler-built component's array, with weak handles for both the array and its element. The diagnostic checks retention across native collections, component rediscovery, and unused-resource unloading, alongside an unrooted resource control. The author probe checks array alias preservation, JSON restoration, and independent cloned array storage with GameObject/Transform references remapped to the clone.

The native-only diagnostic in `tests/S1Interop.Compiler.NativeSerializationSmoke` exposed two independent GC requirements: pointer-aligned reference fields and the native class's `HasReferences` flag. Stock injection failed retention with either requirement missing. Generated field slots are padded to eight bytes, every injected class is prepared before allocation, and string and native object reference writes use Unity's write barrier. The final diagnostic checks both its direct loader fixture and a compiler-built component inheriting serialized fields from an abstract base. Seventeen checks pass across eight forced native-GC frames, including a reclaimed unrooted control string. The compiler-built component also retains a ScriptableObject through unused-resource unloading while an unreferenced ScriptableObject control is reclaimed; ordinary native GC alone kept that control alive and was inconclusive. The diagnostic also verifies that an array stored through the compiler-built library remains alive while its game-data owner is retained, while an unrooted control array is reclaimed. A separate retained array in an injected component field also survives collection and component rediscovery with its content intact. An element written through compiler-lowered reference-array access survives while its game-data array owner is retained; an unrooted element control is reclaimed. The unchanged author probe separately checks JSON round trips, null assignments, native identity, and runtime cloning on both backends, including remapping GameObject and Transform references to their cloned counterparts. Portable tests preserve inferred anonymous-object and tuple names, deconstruction targets, and enumeration through reference fields across a compiler-library boundary. This does not prove concurrent/incremental GC behavior or prefab/AssetBundle script binding.

The intended outcome remains ordinary game-project-like authoring. This is an experimental compiler path toward that outcome, not a declaration that the unlimited compatibility goal has been achieved.

Supported component array fields now become native reference fields automatically, including private `[SerializeField]` arrays and inherited fields in compiler-built libraries. Initializer syntax, nullable/shared declarations, and C# collection expressions with spreads are handled without changing author source. JSON replacement leaves old array aliases intact, null assignment and JSON restoration work, and runtime cloning produces independent array storage. The dual-runtime probe covers int, bool, float, char, and long arrays, including a 64-bit value beyond exact double precision. Native GC checks establish retention through the component field against a reclaimed unrooted array control. This does not establish prefab/AssetBundle script binding, general by-reference field access, or other array element shapes.
