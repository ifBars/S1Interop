# S1Interop 0.1.0-alpha.2

This alpha introduces the source compiler as the default way to build a mod. Write ordinary `ScheduleOne.*` C# and build separate Mono and IL2CPP outputs from the same source.

## Install

Install the [.NET 8 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/8.0), then run:

```console
dotnet tool install --global S1Interop --version 0.1.0-alpha.2
```

If you already installed the tool globally, replace `install` with `update`. Follow [Build your first mod](https://ifbars.github.io/S1Interop/articles/first-mod.html) for game setup, builds, and deployment. Source builds are not required.

## What changed

- One `s1interop` tool handles project creation, setup, and compilation. `s1interop new MyMod --apply` creates a compiler project and pins its local tool version.
- The compiler adapts supported game calls, casts, collections, callbacks, components, and reflection using your local game metadata. Supported collection operations preserve shared game storage.
- Mono authoring references expose supported nonpublic members. Builds check matching game versions and the provenance of generated IL2CPP references.
- The guides now lead from installation to writing game code. Legacy generator workflows are under Advanced.

## Existing projects

Updating the global tool does not migrate a project or update its pinned compiler and build imports. Follow [Bring an existing mod](https://ifbars.github.io/S1Interop/articles/compiler-adoption.html) to adopt the compiler in a separate project.

The older generator workflow remains available through `new --legacy-generator` and the separate `S1Interop.Generators` package. New compiler projects do not need that package. IL2CPP compiler outputs need the matching `S1Interop.Runtime.dll`; follow [Test and distribute](https://ifbars.github.io/S1Interop/articles/distributing-mods.html).

## Tested scope and limits

The compiler has 214 portable contracts. Shared runtime probes passed 127 checks per backend on matching Schedule I **0.4.7f9** installations with **MelonLoader 0.7.3**. Package validation covers an isolated install, project creation, tool restore, setup, and builds against both game reference sets. These checks do not prove arbitrary mod gameplay compatibility.

This remains experimental. Generic and collection flows, reflection, serialized components, assets, and prebuilt libraries still have gaps. Missing native game code cannot be restored by publicizing references. Read [What works and what's missing](https://ifbars.github.io/S1Interop/articles/compatibility.html) and test your mod on each supported runtime before sharing it.
